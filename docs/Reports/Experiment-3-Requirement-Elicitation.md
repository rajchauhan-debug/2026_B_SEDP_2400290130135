# EXPERIMENT 3

## Software Design Principles – Requirement Elicitation

---

## 1. Aim

To identify stakeholders and perform requirement elicitation for the **CampusCareer – Student Placement & Internship Management System**, and prepare user stories and a Requirement Gathering Report.

---

## 2. Objectives

The objectives of this experiment are:

1. To identify the stakeholders of the CampusCareer system.
2. To identify suitable requirement elicitation techniques.
3. To identify functional and non-functional requirements.
4. To develop user personas for different types of users.
5. To prepare user stories with acceptance criteria.
6. To prepare a Requirement Gathering Report.

---

## 3. Stakeholder Identification

| Stakeholder | Role | Requirements / Expectations |
|---|---|---|
| **Student** | Uses the system to find and apply for opportunities | Registration, login, profile, view opportunities, apply, and track application status |
| **Placement Administrator** | Manages placement and internship opportunities | Add/delete opportunities and view applications |
| **System Administrator** | Maintains the system | User management and basic system maintenance |
| **Database** | Stores system information | Secure storage of student, opportunity, and application data |

---

## 4. Requirement Elicitation Techniques

The following techniques are considered for gathering requirements:

| Technique | Purpose | Expected Outcome |
|---|---|---|
| **Interview** | Discuss requirements with students and administrators | Detailed functional requirements |
| **Questionnaire** | Collect feedback from multiple students | User expectations and preferences |
| **Observation** | Understand how students currently search for opportunities | Usability and workflow requirements |
| **User Persona** | Represent different types of users | User-centred requirements |

These techniques include interviews, questionnaires, observation, and user personas as described in the experiment material.

---

## 5. Requirement Findings

Based on the identified stakeholders and elicitation techniques, the following requirements were identified.

### 5.1 Functional Requirements

- Students should be able to register and log in.
- Students should be able to manage their profile.
- Students should be able to view placement opportunities.
- Students should be able to view internship opportunities.
- Students should be able to apply for an opportunity.
- Students should be able to check their application status.
- Administrators should be able to log in.
- Administrators should be able to add opportunities.
- Administrators should be able to delete opportunities.
- Administrators should be able to view student applications.

### 5.2 Non-Functional Requirements

- The system should be simple and easy to use.
- The system should provide quick responses to user actions.
- User and application data should be protected.
- The system should be reliable and available when required.
- The system should be maintainable.
- Only authorized administrators should be able to manage opportunities.

---

## 6. User Personas

### Persona 1 – Regular Student

**Age:** 21  
**Role:** College Student

**Goals:**
- Find suitable placement opportunities.
- Find internship opportunities.
- Apply easily.
- Track application status.

**Pain Points:**
- Information is available through different sources.
- Difficulty in tracking multiple applications.

---

### Persona 2 – Final-Year Student

**Age:** 22  
**Role:** Final-Year Student

**Goals:**
- Find placement opportunities.
- Check opportunity information.
- Track submitted applications.

**Pain Points:**
- Missing important opportunity information.
- Difficulty in keeping track of application status.

---

### Persona 3 – Placement Administrator

**Age:** 35  
**Role:** Placement Administrator

**Goals:**
- Add placement and internship opportunities.
- Remove outdated opportunities.
- View student applications.

**Pain Points:**
- Managing opportunity information manually.
- Tracking student applications.

---

## 7. User Stories

### US1 – Student Registration and Login

**User Story:**

As a student, I want to register and log in to the system so that I can access placement and internship opportunities.

**Acceptance Criteria:**

- Student can create an account.
- Student can log in using valid credentials.
- Invalid login details are rejected.

---

### US2 – View Opportunities

**User Story:**

As a student, I want to view available placement and internship opportunities so that I can find suitable opportunities.

**Acceptance Criteria:**

- Available opportunities are displayed.
- Opportunity details can be viewed.

---

### US3 – Apply for Opportunity

**User Story:**

As a student, I want to apply for a placement or internship opportunity so that I can submit my application.

**Acceptance Criteria:**

- Student can select an available opportunity.
- Student can submit an application.
- Application is stored in the system.

---

### US4 – Track Application Status

**User Story:**

As a student, I want to view my application status so that I can track the progress of my applications.

**Acceptance Criteria:**

- Student can view submitted applications.
- The current status of each application is displayed.

---

### US5 – Manage Opportunities

**User Story:**

As an administrator, I want to add and delete opportunities so that the available placement and internship information remains updated.

**Acceptance Criteria:**

- Administrator can add a new opportunity.
- Administrator can delete an existing opportunity.
- Updated opportunity information is displayed to students.

---

## 8. Requirement Gathering Report

The requirement gathering process identified **students and administrators** as the primary users of CampusCareer.

The major functional requirements include student registration and login, profile management, viewing placement and internship opportunities, applying for opportunities, tracking application status, and administrative management of opportunities and applications.

The major non-functional requirements include ease of use, quick response, reliability, security, and maintainability.

User personas and user stories were prepared to understand user needs and define the expected behaviour of the system.

---

## 9. Result

The stakeholders, requirement elicitation techniques, functional and non-functional requirements, user personas, user stories, and acceptance criteria for the **CampusCareer – Student Placement & Internship Management System** were successfully identified and documented.
